## 🔌 1. 适配器模式（Adapter）——万能"转接头"

小灰："适配器？是不是像手机转接头？"  
大黄："聪明！它就像'万能转接头'，让不兼容的接口能够一起工作。比如欧标插头插不进美标插座，适配器来帮忙！"

现实例子：
• 欧洲插头（圆脚）→ 适配器 → 中国插座（扁孔）

• 老系统接口 → 适配器 → 新系统调用

TypeScript代码示例：

```
// 老系统：圆脚插头
class EuropeanPlug {
    plugIn(): string {
        return "欧洲圆脚插头已连接";
    }
}

// 新系统需要扁孔接口
interface FlatSocket {
    connect(): string;
}

// 适配器：让圆脚插头适配扁孔插座
class PlugAdapter implements FlatSocket {
    private europeanPlug: EuropeanPlug;
    
    constructor(plug: EuropeanPlug) {
        this.europeanPlug = plug;
    }
    
    connect(): string {
        return this.europeanPlug.plugIn() + " [通过适配器转换为扁孔接口]";
    }
}

// 使用
const oldPlug = new EuropeanPlug();
const adapter = new PlugAdapter(oldPlug);
console.log(adapter.connect()); // 输出：欧洲圆脚插头已连接 [通过适配器转换为扁孔接口]
```

比喻：适配器就像"翻译官"——让说英语的老系统跟说法语的新系统顺利"聊天"！

## 🎁 2. 装饰器模式（Decorator）——俄罗斯套娃式增强

小灰："装饰器？是不是像给手机套壳贴膜？"  
大黄："没错！它动态地给对象添加新功能，像俄罗斯套娃一样层层包装，但又不改变对象本身。"

现实例子：
• 咖啡（基础）→ 加糖（装饰）→ 加奶（装饰）→ 加奶油（装饰）

• 文本（基础）→ 加粗（装饰）→ 变红色（装饰）→ 加下划线（装饰）

Python代码示例：
```
from abc import ABC, abstractmethod

class Coffee(ABC):
    @abstractmethod
    def cost(self):
        pass
    
    @abstractmethod
    def description(self):
        pass

class BasicCoffee(Coffee):
    def cost(self):
        return 5
    
    def description(self):
        return "基础咖啡"

class CoffeeDecorator(Coffee):
    def __init__(self, coffee):
        self._coffee = coffee
    
    def cost(self):
        return self._coffee.cost()
    
    def description(self):
        return self._coffee.description()

class SugarDecorator(CoffeeDecorator):
    def cost(self):
        return self._coffee.cost() + 1
    
    def description(self):
        return self._coffee.description() + " + 糖"

class MilkDecorator(CoffeeDecorator):
    def cost(self):
        return self._coffee.cost() + 2
    
    def description(self):
        return self._coffee.description() + " + 奶"

# 使用：像套娃一样装饰
coffee = BasicCoffee()
print(f"{coffee.description()}: ${coffee.cost()}")  # 基础咖啡: $5

sugar_coffee = SugarDecorator(coffee)
print(f"{sugar_coffee.description()}: ${sugar_coffee.cost()}")  # 基础咖啡 + 糖: $6

full_coffee = MilkDecorator(SugarDecorator(coffee))
print(f"{full_coffee.description()}: ${full_coffee.cost()}")  # 基础咖啡 + 糖 + 奶: $8
```
比喻：装饰器就像"时尚穿搭"—基础白T恤（基础对象）→ 加项链（装饰）→ 加外套（装饰）→ 变成潮流达人！

## 🎭 3. 代理模式（Proxy）——明星的"经纪人"

小灰："代理？是不是像明星经纪人？"  
大黄："太对了！代理控制对原始对象的访问，就像经纪人帮明星挡掉不必要的骚扰，只让'合格'的粉丝接触明星。"

现实例子：
• 虚拟代理：图片未加载时显示占位图

• 保护代理：权限检查，只有VIP能访问高级功能

• 远程代理：本地调用，实际执行在远程服务器

Java代码示例：
```
// 主题接口（明星）
interface Image {
    void display();
}

// 真实主题（真实明星）
class RealImage implements Image {
    private String filename;
    
    public RealImage(String filename) {
        this.filename = filename;
        loadFromDisk(); // 加载很耗时
    }
    
    private void loadFromDisk() {
        System.out.println("加载图片: " + filename);
    }
    
    public void display() {
        System.out.println("显示图片: " + filename);
    }
}

// 代理（经纪人）
class ImageProxy implements Image {
    private String filename;
    private RealImage realImage;
    
    public ImageProxy(String filename) {
        this.filename = filename;
    }
    
    public void display() {
        if (realImage == null) {
            realImage = new RealImage(filename); // 懒加载：只有需要时才创建
        }
        realImage.display();
    }
}

// 使用
public class Client {
    public static void main(String[] args) {
        Image image = new ImageProxy("photo.jpg");
        // 此时图片还未加载
        image.display(); // 第一次调用时才加载并显示
    }
}
```

比喻：代理就像"婚前协议"—你想约会（访问对象）？先通过我这一关（代理检查）！

## 🏢 4. 外观模式（Facade）——酒店的"前台接待"

小灰："外观模式是不是像酒店前台？"  
大黄："完美比喻！它提供一个统一的简单接口，来隐藏子系统的复杂性，就像酒店前台帮你处理订房、保洁、维修所有琐事！"

现实例子：
• 电脑开机按钮：一键搞定CPU、内存、硬盘、系统启动等复杂操作

• 电商下单接口：隐藏了库存检查、支付处理、物流安排等复杂流程

C++代码示例：
```
#include <iostream>
#include <string>
using namespace std;

// 复杂子系统类
class CPU {
public:
    void start() { cout << "CPU启动..." << endl; }
};

class Memory {
public:
    void load() { cout << "内存加载..." << endl; }
};

class HardDisk {
public:
    void read() { cout << "硬盘读取..." << endl; }
};

// 外观类（电脑开机按钮）
class ComputerFacade {
private:
    CPU cpu;
    Memory memory;
    HardDisk hardDisk;
    
public:
    void startComputer() {
        cout << "=== 电脑开机过程 ===" << endl;
        cpu.start();
        memory.load();
        hardDisk.read();
        cout << "电脑启动完成！" << endl;
    }
};

// 客户端使用
int main() {
    ComputerFacade computer;
    computer.startComputer(); // 一键开机，不用关心内部细节
    return 0;
}
```
比喻：外观模式就像"餐厅服务员"—你只说"来份套餐"，服务员帮你协调厨师、配菜、摆盘所有复杂流程！

## 🎯 结构型模式对比总结

大黄敲黑板："小灰，记住这几个模式的本质区别："
• 适配器：接口转换（解决兼容性问题）

• 装饰器：功能增强（动态添加新功能）  

• 代理：访问控制（控制对对象的访问）

• 外观：简化接口（隐藏子系统复杂性）
