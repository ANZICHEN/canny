## 内容

📖 第二章：创建型模式——对象的“出生证明”管理大师！

大黄翘着二郎腿说：“小灰啊，今天咱们讲创建型模式。想象你是个‘对象幼儿园园长’，这些模式就是你的招生策略，确保每个对象都出生得优雅、不混乱。创建型模式有5大明星：Abstract Factory、Builder、Factory Method、Prototype 和 Singleton。每个都像魔法咒语，解决不同的对象创建难题。”

小灰挠头：“大黄，我有点懵……为啥要这么麻烦？直接 new 一个对象不香吗？”

大黄弹了小灰一个脑瓜崩：“笨！如果所有对象都硬编码 new，代码会变成‘意大利面条’——改一点就全乱套！创建型模式能让代码更灵活、可复用，比如支持不同主题的UI、动态组装复杂对象，或者保证全局唯一实例。来，咱们一个个拆解！”

### 🏭 1. Abstract Factory（抽象工厂）——生产“主题乐园全家桶”

小灰：“Abstract Factory 是啥？听起来像开工厂的！”  
大黄：“没错！它像个‘主题乐园工厂’，专门生产一系列相关对象。比如迪士尼乐园要造米老鼠、唐老鸭全套角色，而不是单个生产。这样切换主题时，不用重写代码，只需换一个工厂就行。”  
动机：如果代码里硬编码具体类，比如直接 new WindowsButton()，那想换成Mac风格按钮时，得改遍所有代码。Abstract Factory 通过接口隔离，让客户端不依赖具体类。  
结构：
• 抽象工厂（AbstractFactory）：定义创建一系列产品的接口，如 createButton()、createDialog()。

• 具体工厂（ConcreteFactory）：实现接口，生产特定主题的产品，比如 WindowsFactory 造 Windows 风格按钮和对话框。

• 产品族（Product Family）：一组相关产品，如按钮和对话框必须风格一致。

示例代码（简化版）：
```
// 抽象产品：按钮
interface Button { void click(); }
// 具体产品：Windows 按钮
class WindowsButton implements Button {
    public void click() { System.out.println("Windows 按钮被点击！"); }
}
// 抽象工厂
interface GUIFactory {
    Button createButton();
}
// 具体工厂：Windows 工厂
class WindowsFactory implements GUIFactory {
    public Button createButton() { return new WindowsButton(); }
}
// 客户端代码
public class Client {
    public static void main(String[] args) {
        GUIFactory factory = new WindowsFactory(); // 切换为 MacFactory 就能换主题！
        Button button = factory.createButton();
        button.click(); // 输出：Windows 按钮被点击！
    }
}

```

幽默比喻：Abstract Factory 就像点“汉堡套餐”——它保证给你汉堡+薯条+可乐，而不是汉堡+筷子！产品族风格一致，避免混搭车祸现场。  
优点：解耦客户端和具体类，支持快速切换产品族。  
缺点：添加新产品麻烦，得修改所有工厂接口。

### 🏗️ 2. Builder（生成器）——像搭乐高一样组装对象

小灰：“Builder 模式呢？是不是搞建筑的？”  
大黄：“聪明！它像‘乐高说明书’，一步步组装复杂对象。比如建房子：先地基，再墙壁，最后屋顶。避免构造参数太多，让代码清晰易懂。”  
动机：如果对象构造参数多（比如10个），用构造器会变成 new House(地基, 墙, 屋顶, 窗户...)，容易出错。Builder 将构造过程分解，支持链式调用。  
结构：
• Builder（生成器）：定义组装步骤的接口，如 buildBase()、buildWall()。

• Director（导演）：控制组装顺序，调用 Builder 的方法。

• 具体 Builder：实现接口，生产具体产品。

示例代码（建房子例子）：
```
// 产品：房子
class House {
    private String base, wall, roof;
    public void setBase(String base) { this.base = base; }
    public void setWall(String wall) { this.wall = wall; }
    public void setRoof(String roof) { this.roof = roof; }
}
// 抽象 Builder
interface HouseBuilder {
    void buildBase();
    void buildWall();
    void buildRoof();
    House getResult();
}
// 具体 Builder
class ConcreteHouseBuilder implements HouseBuilder {
    private House house = new House();
    public void buildBase() { house.setBase("坚固地基"); }
    public void buildWall() { house.setWall("砖墙"); }
    public void buildRoof() { house.setRoof("瓦片屋顶"); }
    public House getResult() { return house; }
}
// Director：控制组装顺序
class Director {
    public House construct(HouseBuilder builder) {
        builder.buildBase();
        builder.buildWall();
        builder.buildRoof();
        return builder.getResult();
    }
}
// 客户端使用
public class Client {
    public static void main(String[] args) {
        Director director = new Director();
        HouseBuilder builder = new ConcreteHouseBuilder();
        House house = director.construct(builder); // 像搭乐高一样简单！
    }
}
```

幽默比喻：Builder 就像做三明治——你可以选面包、馅料，一步步来，而不是吃“神秘混合体”。  
优点：分离构造过程，支持不同表示。  
缺点：代码量增加，适合复杂对象。

### 🔨 3. Factory Method（工厂方法）——子类决定生啥对象

小灰：“Factory Method 我听过！是不是让子类当老板？”  
大黄：“对！它是个‘定制工厂’，父类定义创建接口，子类决定实例化哪个对象。比如宠物店卖猫或狗，由分店决定具体品种。”  
动机：避免将创建逻辑硬编码在父类中，提高扩展性。比如图形编辑器需要支持多种图形工具。  
结构：
• Product（产品）：抽象接口，如 Animal。

• ConcreteProduct（具体产品）：如 Cat、Dog。

• Creator（创建者）：定义工厂方法 createAnimal()，可能返回抽象产品。

• ConcreteCreator（具体创建者）：重写工厂方法，返回具体产品。

示例代码（宠物店例子）：
```
// 抽象产品
interface Animal { void speak(); }
// 具体产品
class Cat implements Animal {
    public void speak() { System.out.println("喵喵喵！"); }
}
class Dog implements Animal {
    public void speak() { System.out.println("汪汪汪！"); }
}
// 抽象创建者
abstract class PetShop {
    public abstract Animal createAnimal(); // 工厂方法
    public void sellPet() {
        Animal animal = createAnimal();
        animal.speak();
    }
}
// 具体创建者
class CatShop extends PetShop {
    public Animal createAnimal() { return new Cat(); } // 子类决定生猫
}
class DogShop extends PetShop {
    public Animal createAnimal() { return new Dog(); } // 子类决定生狗
}
// 客户端
public class Client {
    public static void main(String[] args) {
        PetShop shop = new CatShop(); // 切换成 DogShop 就卖狗
        shop.sellPet(); // 输出：喵喵喵！
    }
}
```

幽默比喻：Factory Method 是“不要问我生啥，问我儿子！”——父类甩锅给子类，灵活又省心。  
优点：符合开闭原则，易于扩展。  
缺点：每新增一个产品，就得加一个创建者子类。

### 🧬 4. Prototype（原型）——用“克隆术”复制对象

小灰：“Prototype 模式是复制粘贴吗？”  
大黄：“没错！它用‘克隆技术’创建新对象，基于现有原型复制，避免重复初始化。比如游戏里复制怪物，不用重新设置属性。”  
动机：当创建对象成本高（如数据库连接），或需要动态配置时，直接克隆原型比 new 更高效。  
结构：
• Prototype（原型接口）：定义克隆方法 clone()。

• ConcretePrototype（具体原型）：实现克隆，复制自身状态。

示例代码（游戏怪物克隆）：
```
// 原型接口
interface Monster extends Cloneable {
    Monster clone() throws CloneNotSupportedException;
    void attack();
}
// 具体原型
class Dragon implements Monster {
    private String name;
    public Dragon(String name) { this.name = name; }
    public Monster clone() throws CloneNotSupportedException {
        return (Dragon) super.clone(); // 浅拷贝，如需深拷贝需重写
    }
    public void attack() { System.out.println(name + " 喷火攻击！"); }
}
// 客户端
public class Client {
    public static void main(String[] args) throws Exception {
        Monster dragon1 = new Dragon("远古巨龙");
        Monster dragon2 = dragon1.clone(); // 克隆一个！
        dragon2.attack(); // 输出：远古巨龙 喷火攻击！
    }
}
```

幽默比喻：Prototype 就像复印机——为啥重写报告？直接复印改名字！省时省力。  
优点：避免重复初始化，性能高。  
缺点：深拷贝复杂时需小心。

### 👑 5. Singleton（单例）——全球唯一“大BOSS”

小灰：“Singleton 我懂！就是确保一个类只有一个实例，像公司CEO。”  
大黄：“对！它保证全局唯一实例，比如数据库连接池。谁访问都是同一个对象，避免资源冲突。”  
动机：有些对象只需一个，如配置管理器、日志工具。多次实例化会浪费资源。  
结构：
• 私有构造器：防止外部 new。

• 静态实例：全局唯一。

• 静态获取方法：如 getInstance()。

示例代码（懒汉式单例，线程安全版）：
```
class Singleton {
    private static Singleton instance;
    private Singleton() {} // 私有构造器
    public static synchronized Singleton getInstance() { // 加锁保证线程安全
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
    public void showMessage() { System.out.println("我是唯一实例！"); }
}
// 客户端
public class Client {
    public static void main(String[] args) {
        Singleton s1 = Singleton.getInstance();
        Singleton s2 = Singleton.getInstance();
        System.out.println(s1 == s2); // 输出 true，是同一个对象！
        s1.showMessage(); // 输出：我是唯一实例！
    }
}
```

幽默比喻：Singleton 是“单身狗模式”——全世界只有一个你，但谁都可以找你聊天！  
优点：节约资源，控制全局访问。  
缺点：过度使用可能导致全局状态混乱。
